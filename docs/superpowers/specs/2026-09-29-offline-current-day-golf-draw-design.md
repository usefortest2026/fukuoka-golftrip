# 福岡行程：離線、當日自動開啟與高爾夫分組抽籤設計

狀態：已於 2026-09-29 對話中確認

## 背景

這個網站主要在五天福岡高爾夫旅程中以手機使用。此次調整要讓旅途中開啟網站更快、更可靠，並加入當天才會使用的分組抽籤，同時維持目前簡潔、緊湊、容易操作的介面。

## 目標

1. 在旅程日期內，以日本時間自動開啟當天行程。
2. 將網站做成可安裝、可離線開啟的 PWA；基本行程資料即使沒有網路也能閱讀。
3. 在三個高爾夫日的行程底部加入一次性分組抽籤遊戲。
4. 維持中英文版本功能一致，避免增加新的主導覽分頁。

## 不在範圍內

- 不新增「現在／下一站」資訊卡或下一站提示功能；這次只改自動開啟當日行程的行為。
- 不建立帳號、後端、多人同步或跨手機同步。
- 不提供抽籤結果的複製、分享或儲存。
- 不預先下載優惠券圖片；由使用者自行選擇是否下載供離線使用。
- 天氣、Google Maps 與其他外部網站仍需要網路。

## 1. 高爾夫分組抽籤

### 入口與流程

- 入口只出現在 Day 2、Day 4、Day 5 三個高爾夫日的內容最下方，不新增分頁。
- 區塊使用「今日分組抽籤」與一個清楚的開始按鈕。
- 點擊後開啟全螢幕抽籤畫面，六顆寫有名字的高爾夫球先洗牌，再落入「第一組」與「第二組」。
- 動畫約兩秒，不載入額外圖片或第三方動畫套件。
- 結果畫面提供「再抽一次」與「關閉」。再抽一次不另外確認。
- 同一次開啟期間結果保持不變；關閉後即清除，下一次開啟就是全新的抽籤。

### 名單與隱藏規則

畫面只顯示以下六個名字：

- 偉哥
- Asa
- 小林
- Derek
- Jack
- Alex

系統內部將偉哥與 Asa 各視為兩人單位，其他名字各為一人單位：

```text
偉哥 = 2
Asa = 2
小林 = 1
Derek = 1
Jack = 1
Alex = 1
```

這使八位球員能穩定分成 4 人與 4 人兩組。伴侶資訊不顯示、不拆開，也不使用「女伴」等文字。每組標題只寫「第一組／第二組」，不標示可見名字數，避免把可見名字數誤認為實際球員數。

### 隨機演算法

1. 列舉所有加總正好為 4 的名字子集合，其補集也必須加總為 4。
2. 將互為鏡像的兩組組合去重，避免同一分組只是左右對調卻被重複計算。
3. 從有效組合中等機率抽出一個結果。
4. 兩組內的顯示順序再各自洗牌，增加遊戲感。
5. 優先使用 Web Crypto 產生亂數；不支援時才退回 `Math.random()`。
6. 不把結果寫入 localStorage、sessionStorage、IndexedDB、網址或後端。

### 動畫、操作與無障礙

- 動畫以 CSS 和既有圖示完成，避免增加下載量。
- 支援 `prefers-reduced-motion`；啟用減少動態時改為快速淡入結果。
- 全螢幕畫面開啟後鎖定背景捲動、將焦點移入對話框，並可用 Escape 關閉。
- 按鈕保留足夠觸控面積，狀態變化使用可被輔助技術讀取的文字。

## 2. 依日本時間自動開啟當日行程

- 日期判斷統一使用 `Asia/Tokyo`，不依手機目前時區。
- 對應日期如下：

| 日本日期 | 自動開啟 |
| --- | --- |
| 2026-11-06 | Day 1 |
| 2026-11-07 | Day 2 |
| 2026-11-08 | Day 3 |
| 2026-11-09 | Day 4 |
| 2026-11-10 | Day 5 |

- 只在沒有明確指定頁面時自動開啟當天。
- 帶有有效 `?p=dayN` 的直接連結優先，不覆寫使用者指定的日期。
- 使用者手動切換日期後尊重該選擇，不在同一次頁面使用期間自動跳回。
- 旅程日期以外維持目前預設入口（Day 1）。
- 不新增「現在／下一站」卡片；既有導覽不因這項功能擴充新的狀態介面。

## 3. 離線與 PWA

### 基本離線內容

首次成功連線後，自動快取網站外殼與核心資料：

- 中英文入口 HTML
- 共用 CSS 與 JavaScript
- 五天行程內容
- 飯店地址、電話與郵遞區號相關功能
- 行李清單功能
- 分組抽籤功能
- 本機圖示與必要的本機介面資產
- 加密保存的私人資料檔案只以目前的加密形式快取，不新增明文副本

外部球場照片、Google Fonts、Font Awesome、地圖、天氣與外部連結不列為離線成功的必要條件。外部資源失效時，核心文字與操作仍必須可用。

### 快取策略

- 新增 Web App Manifest、Service Worker 與註冊程式。
- 導覽文件採 network-first，連線失敗時回退到已快取版本。
- 版本化的本機靜態資產採 cache-first 或 stale-while-revalidate。
- Service Worker 啟用新版時移除舊版快取，並與目前的 `version.txt` 更新機制協調，避免長期卡在舊版本。
- 瀏覽器不支援 Service Worker 時，網站仍以一般線上網站運作。

### 優惠券離線下載

- 優惠券預設仍維持收合與 lazy loading，不加入初始核心快取。
- 優惠券區塊頂部加入「下載優惠券供離線使用」按鈕。
- 點擊後下載所有收錄在網站內的本機優惠券圖片並顯示進度。
- 全部成功後顯示「已可離線使用」。
- 部分失敗時顯示未完成數量並提供重試；不把部分成功誤報為全部完成。
- 下載狀態以實際 Cache Storage 內容判斷，不依賴抽籤結果或私人資料。

### 安裝提示

- 在「更多 > 總覽」底部加入精簡的離線／加入主畫面說明，不新增主導覽分頁。
- 支援安裝提示的瀏覽器可使用原生安裝流程。
- iPhone／iPad 顯示簡短的「分享 → 加入主畫面」說明。
- 已安裝或不支援安裝提示時，介面自然降級，不阻礙其他內容。

## 4. 效能與隱私

- 抽籤不增加大型圖片、框架或第三方程式庫。
- 優惠券圖片維持按需載入，只有使用者主動下載時才進入離線快取。
- 六個名字是暱稱，會存在公開的前端程式中；不加入伴侶姓名或其他額外個資。
- 離線功能不得把原本受保護的私人資料另存成未加密版本。

## 5. 中英文一致性

- 中文與英文頁面都提供相同的三項功能與相同的分組規則。
- 名字維持原樣，不翻譯。
- 按鈕、狀態、錯誤與安裝說明各自使用對應語言。

## 6. 錯誤處理

- Service Worker 註冊失敗不影響正常線上瀏覽。
- 離線但尚未快取的外部功能要顯示簡短、可理解的需要網路提示。
- 優惠券下載失敗可重試，且保留已成功下載的部分。
- 抽籤若偵測到無有效 4+4 組合，停止動畫並顯示可重試的錯誤，不呈現錯誤分組。

## 7. 驗證方式

### 自動測試

- 日本時間在五個日期與跨日邊界時會選到正確 Day。
- 有效 `?p=dayN` 會覆寫自動日期；無效值安全回到預設。
- 所有抽籤結果都包含六個名字各一次，兩組權重皆為 4。
- 偉哥與 Asa 永遠以不可拆分的兩人單位計算。
- 鏡像組合不重複加權，抽籤只從有效分組中選擇。
- 關閉後重新開啟會回到尚未抽籤狀態，且無任何儲存寫入。

### 瀏覽器與離線測試

- 抽籤入口只出現在 Day 2、Day 4、Day 5 最下方。
- 手機尺寸與桌面尺寸皆可完成開啟、抽籤、再抽與關閉。
- 鍵盤焦點、Escape 關閉與 reduced-motion 正常。
- 首次連線載入後切為離線，五天行程與核心工具仍可使用。
- 優惠券在未主動下載前不保證離線；下載完成後離線可顯示。
- 發布新版本後可取得新版，不會永久使用舊快取。

## 8. 交付、發布與回退

- 實作完成並通過本機測試後，只提供本機預覽給使用者驗收，暫不 push 或部署。
- 使用者測試完成並明確同意發布後，才更新正式版本、push 並部署到現有 GitHub Pages。
- 部署後以正式網址進行手機尺寸的線上與離線 smoke test。
- 若正式版出現問題，使用 Git revert 回退此次功能提交並重新部署，保留完整歷史。
